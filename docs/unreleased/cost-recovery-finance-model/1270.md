`optimize configs` gains `--assumptions`, `physics` (the default) or `spreadsheet`, and ranks every config, computes the configured-rate trade-off and runs the sensitivity panel under that mode's `FinanceConfig`, `finance.with_own_use_basis` of the scenario's, as `finance run` computes each mode (§3, *Override (spreadsheet-assumption) path*): `physics` clears any override, and `spreadsheet` keeps the scenario's or sets 0.70. `--assumptions both`, which names two assumptions, is refused as a configuration error before any simulation; run once per assumption. The 0.5.0 tag ranks under the scenario's `finance:` block as written, so on `scenarios/bristol-fin-calibration.yaml`, whose block sets 0.70, the ranking, the trade-off and the sensitivity panel are now physics' where the tag ranked under the override; `--assumptions spreadsheet` reproduces the tag's ranking. Scenarios that set no override rank as before. The ranking report now names its assumption on its first line, `Self-consumption assumption: **Physics**` or `Self-consumption assumption: **Spreadsheet (70% self-consumption)**`, above `## Cost-Recovery Rank`. Readers of the report read the assumption from that line when they re-pin, and pass `--assumptions spreadsheet` to rank a calibration scenario under its override.
