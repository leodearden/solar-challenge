`optimize.RankedSweep` gains a last field, `self_consumption_override` (default `None`): the `FinanceConfig.self_consumption_override` every config's finance sets, `None` when every config is solved on simulated own-use (`finance.OwnUseBasis.SIMULATED`). `run_sweep` records it and, as it already does for the retained-cash floor, requires it to be one across configs: it refuses configs whose finance blocks set two overrides with a `ValueError` naming both configs and both values, before any simulation, where the 0.5.0 tag ranks them together, each solved on its own assumption. `sensitivity_panel` likewise refuses a `baseline` whose `self_consumption_override` differs from `base_configs`', before any simulation. `board_report.generate_config_ranking_report` now opens with `Self-consumption assumption: **Physics**` or `Self-consumption assumption: **Spreadsheet (<x>% self-consumption)**`, the label `finance run` heads that assumption's column with, and a blank line above `## Cost-Recovery Rank`, where the tag's ranking report opens with that heading; it names the assumption even when no config is feasible. When they re-pin, consumers put every config's finance on one assumption, e.g. with `finance.with_own_use_basis` on the base scenario's finance, before `enumerate_configs`, and read the report's first heading after its assumption line.
