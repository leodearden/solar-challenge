A parallel `FleetRunner` (`simulate`, `simulate_each`) whose worker process ends
abruptly, e.g. through an out-of-memory kill, fails every unfinished home with one
`BrokenProcessPool`. That exception now carries the note "the process pool broke before
home {i} ({name!r}) of fleet {k} ({fleet name!r}) finished; the process that ended may
have been simulating another home", which names whichever unfinished home's future
reported first. A failed home's own exception keeps task 879's note, "simulating home
{i} ({name!r}) of fleet {k} ({fleet name!r})"; before this change a broken pool got
that note too, which claimed that the home it named had failed. The 0.5.0 tag's
`simulate_fleet` raises `BrokenProcessPool` with no note. Consumers change nothing when
they re-pin; code that reads the note to find the failing home should take a
`BrokenProcessPool`'s note as naming only a home that had not finished.
