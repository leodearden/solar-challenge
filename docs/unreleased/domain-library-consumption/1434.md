`GridServicesAtEvents` takes all seven of its fields with no default,
including the four per-window fields task 837 adds, which 837's note had
defaulting to `()`, so `GridServicesAtEvents(...)` without
`per_window_avail_p50_kw`, `per_window_avail_p90_kw`,
`per_window_displaced_self_use_kwh_per_event` or
`per_window_displaced_import_gbp_per_year` raises `TypeError`. Construction,
and `dataclasses.replace` alike, raises a ValueError for a breakdown with no
event window, a per-window field without one entry per event window (as many
as `per_window_avail_kw` holds), a figure below 0 or NaN, or an
`annual_income_gbp` that is not `sum(per_window_income_gbp)`, naming the
invariant and the values that break it. The 0.5.0 tag accepts any tuples and
any total. When they re-pin, consumers that take the breakdown from
`compute_grid_services_at_events` need no code change, since it returns one
that holds every invariant; one that builds a breakdown itself, a test fixture
say, passes every per-window field with one entry per window and an
`annual_income_gbp` equal to the sum of its `per_window_income_gbp`. The
platform builds none.
