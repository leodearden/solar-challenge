`FleetConfig` and `FleetResults` are frozen, and `FleetConfig.homes`,
`FleetResults.per_home_results` and `FleetResults.home_configs` are tuples. A
list passed for one of them is stored as a tuple, so building them with lists
still works at run time, and a fleet's results no longer share its
configuration's list of homes. `FleetResults` checks that it holds at least one
home and one `HomeConfig` per home's results when it is built, and only then:
the fields cannot change afterwards. Assigning a field, such as
`results.home_configs = ()`, raises `dataclasses.FrozenInstanceError`, and
appending to one, such as `results.home_configs.append(home)`, raises
`AttributeError`; the 0.5.0 tag accepts both. Consumers that re-pin see the
fields typed as tuples in a type checker: they pass tuples, or keep passing
lists, and build a changed fleet or result with `dataclasses.replace(...)`
instead of assigning or appending.
