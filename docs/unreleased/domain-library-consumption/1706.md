`FinanceConfig` gains a last field, `battery_inverter_cost_per_kw_gbp`, default
`0.0`: the battery inverter-charger's capex per kW of each battery's
`max_discharge_kw`, a finite number of at least 0, refused naming
`battery_inverter_cost_per_kw_gbp`. Its positional construction is unchanged. A
`finance:` block reads it as a key of the same name, and `scenario_knobs` gains
its finance knob of the same name. The 0.6.0 tag has none of these. Consumers
need no change when they re-pin.

`scenario_knobs` gains the `HOMES` knob `battery_power_kw`, registered after
`battery_capacity_kwh`. It sets `max_charge_kw` and `max_discharge_kw` of each
home's battery alike and leaves a home without a battery unchanged, so
`fleet sweep --param battery_power_kw` sweeps it. A power `BatteryConfig`
refuses is refused as it refuses it, naming `max_charge_kw`. The 0.6.0 tag has no
such knob.

`optimize.ConfigPoint` gains a last field, `battery_kw`, default `None`: the
battery's charge and discharge power in kW, a finite number greater than 0,
refused naming `battery_kw`. When set, the `battery_power_kw` knob sets every
home's `max_charge_kw` and `max_discharge_kw` to it; `None` keeps each home's own
battery power, so a point built as before sweeps exactly as before. A point whose
`battery_kwh` is 0, no battery, is refused when it sets `battery_kw`, naming
`battery_kw` and `battery_kwh`. `optimize.enumerate_configs` and
`optimize.iter_configs` gain keyword-only `battery_kw`, default `None`, parallel
to `battery_kwh`: the i-th power goes with the i-th size, and a length other
than `battery_kwh`'s raises `ValueError` naming both parameters and their
lengths.

`optimize.ConfigResult` gains two stored fields after
`baseline_surplus_per_home_gbp`, so a hand-built `ConfigResult` now passes them:
`n_homes`, the fleet's homes, a whole number of at least 1, and
`year_one_grid_services_income_gbp`, the fleet's grid-services income in year 1,
the projection's age-0 income, a finite number of at least 0; each is refused
naming it. Two read-only properties divide by `n_homes`: `capex_per_home_gbp`
and `grid_services_income_per_home_gbp`, which under `capacity_at_events`
pricing is the events income per home. `run_sweep` fills both fields.

`optimize.RankedSweep` gains a last field, `reference`, so a hand-built
`RankedSweep` now passes it: the reference configuration's own `ConfigResult`,
feasible or not, which must be one of `results` (the same object) or a result
whose config is one of `infeasible`, else `ValueError` naming the reference.
`RankedSweep.against_reference(result)` returns
`optimize.ReferenceComparison(result, reference)`, whose read-only
`extra_capex_per_home_gbp` and `outlay_change_gbp` are the result's capex per
home and representative outlay less the reference's, and whose `pays_for_itself`
holds when the result is feasible and its outlay is not above the reference's.
`optimize.default_reference(points)` returns the point with the least `pv_kwp`,
then `battery_kwh`, then `battery_kw` (`None` first), then `inverter_kw`, and
raises `ValueError` for no points. `optimize.run_sweep` gains keyword-only
`reference`, default `None` for `default_reference` of the configs' points; a
reference that is not one of them raises `ValueError` naming it and the points,
before any simulation. The ranking is unchanged.

`board_report.generate_config_ranking_report`'s Cost-Recovery Rank table gains a
line above it naming `ranked.reference` with its binding label ("Marginal columns
compare each configuration against the reference **<label>** (<binding>)"), and
four last columns: "Extra CapEx vs Reference (£/home)" (signed whole pounds),
"Outlay Change vs Reference (£/yr)" (signed, two decimals), "Grid Services Income
Yr 1 (£/home)" and "Pays For Itself" (yes or no); the reference's row is
suffixed " (reference)". A config whose `battery_kw` is set is labelled
"4.0 kWp / 10.2 kWh at 3.7 kW / 3.7 kW" in every table and the sensitivity
section; one without keeps "4.0 kWp / 5.0 kWh / 5.0 kW".

`optimize configs` gains `--battery-kw`, comma-separated battery powers in kW,
one per `--battery` size in the same order, each setting that size's charge and
discharge power alike, and `--reference`, the configuration the marginal columns
compare against, written `PV,BATTERY,INVERTER` with a fourth value, `BATTERY_KW`,
exactly when `--battery-kw` is given, by default the smallest battery at the
smallest PV. Each is refused before any simulation with a `Configuration error:`
naming it: a `--battery-kw` count other than `--battery`'s (naming both flags
and counts), a `--reference` of the wrong arity (naming its form), and a
`--reference` that is not one of the sweep's configurations (listing each in the
same comma form).
