`WeatherCache` stores each entry as one file,
`<prefix>_<hash>.csv`: a first line of JSON naming the timezone and frequency of
the frame's index, then the frame as CSV, written beside the entry and replaced
whole by one `os.replace`; the 0.5.0 tag writes a CSV and a `.meta.json`
sidecar. `get` returns the frame `put` stored, or `None` when there is no
entry; for an entry file holding anything else it raises `ValueError` naming
the file, where the tag's `get` returned whatever `read_csv` made of the CSV,
restoring the index's timezone and frequency only when the sidecar was there.
Every entry's key changes (key version 3), so each entry written before the
change is ignored, `get_tmy_data` fetches each such TMY afresh from PVGIS at
its first call ([Network I/O](../../domain-library-consumption.md#network-io)),
and `clear()` removes those files too. Consumers rebuild any pre-built cache
with `WeatherCache.put(df, "tmy", location)` when they re-pin, and read entries
only through `WeatherCache.get`, never from their files.
