`SimulationWindow`, the type the task 777 line introduces, now raises
`ValueError` when it is built with a `first_day` or `last_day` whose type is
not exactly `datetime.date`, a `pd.Timestamp` or a `datetime` among them, or
with a `cadence` whose type is not exactly `datetime.timedelta`, such as a
`pd.Timedelta`, naming the field and the value. Before this change a window
with two `pd.Timestamp` days, or with a `pd.Timedelta` cadence, built: a
web-app save of a summary carrying the first kind wrote its days as datetime
text, which loading the run then refused, and a save of one carrying the second
failed. A `pd.Timestamp` or `datetime` day beside a `date` raised `TypeError`.
The window `SimulationWindow.of_index` gives, and so `SimulationResults.window`
and the `window` that `calculate_summary` gives a `SummaryStatistics`, already
holds exactly these types, as does the window `simulate_home` runs over, so no
result changes. The 0.5.0 tag has no `SimulationWindow`. Consumers that build a
window from pandas values pass `Timestamp.date()` and
`Timedelta.to_pytimedelta()` when they re-pin.
