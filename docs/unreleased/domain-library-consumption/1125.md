`solar-challenge validate config` reads the `seg:` and `finance:` blocks of a
`homes:`, `fleet_distribution:` or home file with the parsers `finance run`,
`home run` and `optimize configs` read them with (`parse_seg_rate` and
`parse_finance_config`), as it already read a `scenario:` file's. A value one of
them refuses, e.g. `rate_pence_per_kwh: .nan` or `event_hours: .inf`, is that
file's ERROR row naming the field and the value, where the 0.5.0 tag read
neither block. This supersedes the task 862 line's "still does not read a fleet
file's `finance:` block". No value a public name returns changes, so consumers
need nothing when they re-pin; a file that `validate config` passed with such a
value now fails it, as the commands that run the file already did.
