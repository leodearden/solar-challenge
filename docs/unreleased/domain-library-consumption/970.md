`generate_finance_report` and `generate_config_ranking_report`, the board's reports that `finance run` and `optimize configs` print, move from `solar_challenge.output` to the new module `solar_challenge.board_report`; neither is frozen, and the platform imports neither. `solar_challenge.output` keeps per-run output: the CSV export, the summary and community reports, and seasonal and period aggregation. Both reports now raise `ValueError`, naming the binding, for a cost-recovery solution or config whose `binding` is not one of `'floor'`, `'rate_clamped_zero'` and `'infeasible_above_retail'`, where the finance report printed it as *✘ INFEASIBLE: required rate exceeds retail* and the ranking report printed the raw string. A `CostRecoverySolution` already refuses any other binding when it is built, so only a solution that bypassed that check reaches the finance report's refusal; a `ConfigResult` has no such check, so the ranking report now refuses one built directly with any other binding. The grid-charge forecast notice that both board reports and output's summary and community reports print, which the 0.5.0 tag does not have, is rendered by one public function, `output.grid_charge_forecast_notice`. The move changes no report's text. Consumers that import either board report import it from `solar_challenge.board_report` when they re-pin.
