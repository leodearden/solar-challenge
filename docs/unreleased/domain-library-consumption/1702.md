`DispatchDecision` gains a last field, `export_kw`, default `0.0`: the battery
power in kW a strategy asks for beyond the home's shortfall, sent to the grid.
It is finite and at least 0, and is refused above 0 alongside a `charge_kw` or
`grid_charge_kw` above 0, as `discharge_kw` is, with the message
`Cannot charge and export simultaneously` or
`Cannot grid-charge and export simultaneously`. `simulate_timestep` refuses an
`export_kw` above the headroom the battery's `max_discharge_kw` leaves after the
step's shortfall, before the battery moves. It discharges `discharge_kw` and
`export_kw` together, serves the home's shortfall first from what the battery
delivers, and books the rest as grid export. `EnergyFlowResult` gains a last
field, `battery_export`, default `0.0`: the kWh the battery sent to the grid,
a part of both `battery_discharge` and `grid_export`, as `grid_charge` is of
`battery_charge` and `grid_import`, so the bus identity is unchanged. A
decision that asks for no export settles exactly as before, with
`battery_export` 0.0. `SimulationResults`, reached through
`FleetResults.per_home_results`, gains a last field, `battery_export`, default
`None`: the power in kW the battery sent to the grid each row, under the column
`battery_export_kw` and the amount `battery_export_kwh`. `simulate_home` sets it
only when some row of the run exported battery energy, so a run with no export
has no such series, column or amount, as before. The 0.6.0 tag has none of the
three fields. Consumers need no change when they re-pin.
