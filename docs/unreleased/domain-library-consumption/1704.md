`GridServicesEventsConfig` gains three last fields, so its positional
construction is unchanged. `participation`, default `"observed"`, is held as the
`gridservices.EventParticipation` member it names: `observed`, the fleet runs its
own dispatch and is priced from the spare capacity it leaves, or `dispatched`,
the fleet is enrolled, each battery home discharging at full power through each
drawn event window; any other value is refused naming
`GridServicesEventsConfig.participation` and both values.
`gridservices.EventParticipation`, reached through that field, is a `StrEnum`
whose `parse(value, *, what)` returns the member a value names and refuses
anything else as `GridServicesBand.parse` does. `event_day_seed`, default `0`,
is the seed the fleet's event days are drawn with, a whole number of at least 0,
refused naming `event_day_seed`. `site_export_limit_kw`, default `None` for no
limit, is the most a home may export in a step in which its battery exports in
an event window, PV excess included, a finite number of at least 0, refused
naming `site_export_limit_kw`; it does not curtail PV export in a step in which
the battery exports nothing. A `capacity_at_events` block reads each as a key of
the same name; a null `participation` or `event_day_seed` is refused, and a null
`site_export_limit_kw` is no limit. The 0.6.0 tag has none of these. Consumers
need no change when they re-pin.
