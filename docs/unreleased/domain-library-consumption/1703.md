`BatteryConfig` gains a last field, `event_discharge`, default `()`: the
battery's resolved grid-services event windows, a tuple of
`dispatch.EventDischargeWindow`, held as a tuple and refused, naming
`event_discharge[i]`, when an element is not one. `dispatch.EventDischargeWindow`,
reached through that field, is a frozen dataclass of `days`, a tuple of dates,
and `hours`, a tuple of clock hours: it covers every listed hour of every listed
day, both read on the step timestamp's own clock. Each day must be exactly a
`date`, so a `datetime` or `pd.Timestamp` is refused naming `days[i]`; each hour
is a whole number from 0 to 23, as `gridservices.EventWindow` reads its hours,
refused naming `hours[i]`; an empty `days` or `hours`, or one that repeats a
day or an hour, is refused naming it; and each is held sorted, so two windows
that cover the same minutes are equal and hash equal.
`dispatch.EventDischargeStrategy(base, windows, *, max_discharge_kw)` wraps any
strategy: in a minute a window covers it asks for no charge, a `discharge_kw`
equal to the step's shortfall, an `export_kw` equal to the headroom the
battery's discharge limit, `max_discharge_kw`, leaves after that shortfall, and
no grid charge; at every other minute it returns the base's decision unchanged,
holding no charge back for a window. Its name is `event_discharge(<base>)` and it
charges from the grid as its base does. Its `max_discharge_kw` must equal the
battery's `Battery.max_discharge_kw` for as long as it is used: after a
battery's config is replaced by one with a lower limit, a window's export is
refused by `StepLimits.require_admissible`. `dispatch.build_dispatch_strategy` gains
keyword-only `event_discharge` and `max_discharge_kw` and wraps the strategy it
builds in them, after every refusal, through `dispatch.with_event_discharge`,
which returns the strategy itself when there are no windows; `build_dispatch_strategy`
refuses windows given with no `max_discharge_kw`, naming both. `simulate_home`
runs a battery's windows over the strategy its `dispatch_strategy` names, or over
a `strategy=` override, and the run's `strategy_name` is then
`event_discharge(<base>)`; `simulate_community` does the same for a community
battery. A battery with no windows runs exactly as before. A battery has no
YAML key for its windows, so `scenario_writer` refuses a battery that carries
any, naming `event_discharge`. The 0.6.0 tag has none of these. Consumers need no
change when they re-pin.
